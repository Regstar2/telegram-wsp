# Telegram-WSP 13.2.2 (WSP 4) — кандидат

## Изменение относительно v13.2.2-wsp.3

- Telegram upstream: **13.2.2 (7303)**, исходный pin `21f7d109da6ab3506c9e9577f98c6a38771ab335` — без изменений.
- TgWsProxy core: `515fc50af9797c69722f14409dedcaf96868d9ce` → `a57597c81a6b32291476c459bc418b6e2b07a70c`.
- В Cloudflare Proxy MTProto и SOCKS5 TLS SNI использует **базовый домен**, WebSocket Host остаётся `kwsN.<domain>` и путь `/apiws`.
- Сохраняются IP fallback, Direct WS, Worker и порядок маршрутов Auto на Wi-Fi/mobile.
- Источник: [Android #156](https://github.com/Regstar2/tg-ws-proxy-android/issues/156), [PR #157](https://github.com/Regstar2/tg-ws-proxy-android/pull/157); backport: [tgwsproxy-core PR #10](https://github.com/Regstar2/tgwsproxy-core/pull/10).

## Риски

- Исправление SNI/Host проверено исходным Android-приложением в одной тестовой среде; это не автоматическая приёмка собранного Telegram-WSP APK.
- Существующий native WebSocket TLS-код содержит `InsecureSkipVerify=true`, что исключает полноценную проверку подлинности TLS peer. Требуется отдельное исправление: [Android #158](https://github.com/Regstar2/tg-ws-proxy-android/issues/158).
- Исторические ограничения связности CF Proxy в отдельных мобильных сетях не устранены и не должны трактоваться как исправленные ([Android #154](https://github.com/Regstar2/tg-ws-proxy-android/issues/154)).
