# Telegram-WSP v13.1.1-wsp.3

[Русский](v13.1.1-wsp.3.md) · **English**

## About this release

Compatible Telegram-WSP 13.1.1 (Telegram build 7237) update, WSP revision 3. It updates the embedded TgWsProxy native routing runtime from the Android fork without changing the pinned Telegram upstream or installing a separate TgWsProxy application.

## Highlights

- Handle complete Cloudflare Proxy domain pool exhaustion without flooding diagnostics.
- Cancel stale CF dial/TLS operations when the proxy stops or the route changes.
- Improve WebSocket/TLS interoperability and Worker transport/failover paths.

## Changes

### Fixed

- CF Proxy: per-DC cooldown, in-flight reservations, exhausted-pool classification and bounded repeated-failure logging.
- MTProto: associate telemetry with route policy generations, avoiding misleading fallback attribution after reconfiguration.
- CF/WebSocket: cancellation and TLS handshake failure handling.
- Worker: TLS transport, failover, route diagnostics and connection handling.

### Changed

- Updated reusable `tgwsproxy-core` while preserving Telegram-WSP-specific route order, AWG configuration and route policy restrictions.
- Telegram upstream remains `13.1.1`, package ID remains `org.telegram.messenger.web`.

## Installation and updating

Download the published `Telegram-WSP-release.apk` from [GitHub Releases](https://github.com/Regstar2/telegram-wsp/releases/tag/v13.1.1-wsp.3). It may be installed over WSP 2 when the Android package and signing certificate match, without removing app data. The built-in updater reads `latest.json` and launches the system package installer with user confirmation. See `minimumSdk` in the actual release metadata for the OS requirement.

## Verification

The project uses TgWsProxy Core Go/Android/AAR checks, Telegram-WSP integration CI, and a signed release pipeline. Actual results for this revision can be inspected in [Telegram-WSP Actions](https://github.com/Regstar2/telegram-wsp/actions) and [Core Actions](https://github.com/Regstar2/tgwsproxy-core/actions). Passing a build does not by itself establish connectivity in every real-world network.

## Known issues

CF Proxy, Worker and WARP availability depend on the network and available endpoints. This update cannot guarantee bypass of external connectivity restrictions. Real-device routing acceptance is separate from compilation.
