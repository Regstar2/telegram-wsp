## Cloudflare Proxy: выбор WS/80 или WSS/443

В настройках «Встроенный прокси» появился переключатель **«Отключить TLS для CF Proxy»**.

- **Включён (по умолчанию для новой настройки):** Cloudflare Proxy использует WebSocket через порт 80 без TLS-транспортного шифрования.
- **Выключен:** Cloudflare Proxy использует WSS через порт 443 с TLS.
- Ранее сохранённое значение сохраняет приоритет перед умолчанием.
- Значение сохраняется в настройках приложения и передаётся core через `@cfproxy_no_tls=1` или `@cfproxy_no_tls=0`; если встроенный runtime работает, изменение вызывает его реконфигурацию.

Переключатель касается **только** CF Proxy. Он не управляет TLS для Worker, WARP/AmneziaWG, Direct или HTTPS-запросов встроенного updater. Отсутствие TLS у WS/80 означает, что WebSocket-транспорт не защищён TLS; не следует считать этот режим эквивалентом WSS/443 по конфиденциальности и проверке сервера.

## Получение и проверка

Скачайте `Telegram-WSP-release.apk` со [страницы релиза](https://github.com/Regstar2/telegram-wsp/releases/tag/v13.2.2-wsp.5). Вместе с APK опубликованы `latest.json`, `SHA256SUMS.txt`, `SOURCE_MANIFEST.json` и архивы Corresponding Source.

SHA-256 APK, указанный в опубликованном release metadata:

```text
d14630a2aa422666a38caf0f95adbc2eb26979689373a428e721ed35299b3775
```

Проверка совпадения SHA-256 подтверждает целостность скачанного файла относительно релиза; подлинность подписи APK следует проверять отдельно. Совпадение package ID и подписи необходимо для обновления поверх предыдущей установленной версии.

## Границы проверок

Наличие опубликованного APK и source artifacts не доказывает работоспособность Cloudflare-доменов, Worker или AWG в любой сети. Успешная компиляция Android overlay тоже не заменяет сетевой тест на устройстве.
